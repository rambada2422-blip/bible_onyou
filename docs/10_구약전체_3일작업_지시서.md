## 3. 목표와 범위

3일 뒤의 모습: 휴대폰에서 미리보기를 열면 **구약 전체의 흐름(10개 시대, 40장면)을 처음부터 끝까지** 따라갈 수 있다.
- 40장면 모두: 도착(최현 박사의 통신: 이 시대에서 구할 재료) → 그 시대 사람과 동행하며 묻고 듣기(기록된 말만, 장절과 함께) → 지켜보기(대목) → 관문(나이 단계별 성경 물음) → 재료를 얻음 → 오늘의 물음(최현 박사) → 말씀 카드 → 마무리. 3D가 없는 장면은 **이야기 카드**(그림 배경 + 대목 글 + 세 아이의 말)로 보여 준다.
- 3D 대표 장면(장면표의 12개, 순서대로 되는 만큼): 직접 걸어 다니며 부품 3개를 찾고 사건을 지켜본다.
- 못 끝낸 것은 진행표에 남긴다. **흐름이 끝까지 이어지는 것**이 장면 하나의 완성도보다 먼저다.

- 2~4단계(흐름이 끝까지 이어짐)를 **첫날 안에** 끝내고 미리보기를 갱신한다. 그다음 5~7단계.
- 압도 장면: 3일 범위에서는 게임 안의 효과(`fx.js`: 불, 빛, 물결)로 만든다. Blender 영상은 장면 하나에 CPU 계산이 2~3시간 걸리므로 7단계가 끝나고 시간이 남을 때만, 장면표의 후보 순서대로 한다.

### 4.1 3D 장면 하나의 점검 (대표 확인 대신)

1. 자료의 `design3d`(본문 근거가 붙은 인물·물건·지형, `never`)만 그린다. 본문에 없는 것은 넣지 않는다.
2. 부품 3곳은 사건의 자리에서 떨어진 곳. 아이는 사건에 끼어들지 않는다(목격자).
3. 자동 걷기 시험을 장면마다 추가해 3단계 나이로 끝까지 통과시킨다. **찍은 화면을 직접 열어 본다.**
4. 작성 과정을 보지 않은 에이전트에게 화면과 장면 배치를 본문과 대조하게 한다(방향, 거리, 순서, 인물의 행동).
5. 휴대폰 크기(390×844)에서 글이 잘리지 않는지, 초당 장면 수 표시(주소 끝 `#fps`)로 느려지지 않았는지 본다.
6. 통과하면 커밋·푸시, 진행표 갱신.

## 5. 스스로 정하는 규칙 (확인 버튼 없이)

**묻지 않고 한다**: 파일 읽기·쓰기, 새 파일, 묶기, 시험, 에이전트 실행, 작업 브랜치 커밋·푸시, 미리보기 갱신, 패키지 설치(0원), 진행표·문서 갱신.

**하지 않는다** (필요해 보이면 진행표의 "대표 결정 대기"에 적고 다른 일을 계속한다):
- 돈이 드는 것(유료 서비스, API 키 과금), 새 외부 서비스 가입
- `main`에 병합·푸시, PR 만들기, 기록 다시 쓰기(force push), 파일 대량 삭제
- `00_공통규칙서.md`의 규칙 바꾸기, 감수 상태를 "감수 완료"로 쓰기
- 외부로 보내기(메일, 메시지), 아이들에게 공개

**판단이 갈릴 때의 기본값**:
- 신학·표현: 더 좁은 쪽(본문이 말하는 만큼만, 그리지 않는 쪽)을 고르고 진행표에 "감수 때 확인"으로 적는다.
- 품질과 범위가 부딪히면: 흐름이 끝까지 이어지는 쪽이 먼저.
- 같은 방법이 두 번 실패하면 그 방법을 버리고 원인을 진행표에 한 줄로 적는다.
- 전제가 무너졌으면(예: 틀을 일반화하다 호렙 산이 깨짐) 되돌리고, 작은 걸음으로 다시 한다.

## 7. 멈춤에 대비한다

- 주간 사용량 한도나 컨테이너 정지로 작업이 끊길 수 있다. **단계와 장면이 끝날 때마다 커밋·푸시**하고 진행표에 "다음에 할 일"을 한 줄 적는다. 다시 시작한 세션은 진행표부터 읽는다.
- 대화가 조용하면 컨테이너가 정지되어 백그라운드 계산이 꺼진다. 긴 계산(Blender)은 끝날 때까지 기다리는 작업을 세션에 함께 걸고, 이미 한 것을 건너뛰게 만든다.
- 컨테이너가 바뀌면 `tools/setup_env.sh`를 다시 실행한다.

## 8. 이전 세션에서 배운 것 (요약. 자세한 것은 `05` 5절)

- three.js r128, 묶음 도구 없음, 전역 `BO3D`. 스크립트 순서는 `web3d/index.html`과 `tools/build3d.js`에 있다. GLB는 `glbdata.js`에 글자로 들어간다(`build3d.js`가 만든다).
- 휴대폰의 미리보기에서는 주소 끝 `#...`가 전달되지 않는다. 시험용 선택은 화면 안의 버튼으로 만든다.
- 화면 없는 환경의 3D 시험은 느리다(한 번에 5~10분, CPU 4개). 시험을 여러 개 동시에 돌리면 서로 느려진다.
- bpy에서 Cycles는 `addon_utils.enable('cycles')` 뒤에. 유체 계산(Mantaflow)은 이 환경에서 안 된다. 다시 시도하지 않는다.
- 게임은 꼭짓점 색을 화면 값 그대로 쓴다. 같은 모델을 Cycles로 그릴 때는 감마 2.2 보정이 필요하다(`moses_glb_video.py`).
- 천 시뮬레이션은 겉옷에는 잘 되지만 얇은 머리쓰개는 찢어져 보였다. 머리쓰개는 직접 만든다.
- 검증에서 되풀이해 나온 실수: 본문에 없는 인물의 행동, 본문 문장을 거의 그대로 옮긴 글, 장절이 그 내용을 담고 있지 않은 것, 장면의 방향과 거리.

## 9. 하지 말 것

- 하나님과 천사를 형상으로 그리지 않는다. 하나님의 음성을 소리로 만들지 않는다. 말씀을 지어내지 않는다.
- 개역개정·개역한글 본문을 게임·문서·코드에 싣지 않는다(`ref/`는 저장소에 넣지 않는다).
- 세 아이가 사건의 결과를 바꾸게 하지 않는다. 성경 인물과의 대화는 규칙서 13.3의 동행 문답뿐이고, 그 인물의 말은 본문에 기록된 것만 쓴다. 3D 장면의 부품 찾기는 "그 시대의 재료 얻기"로 바꾼다(13.2. 기적이나 거룩한 것에 속한 것은 재료가 아니다).

- 자동 시험을 통과시키려고 시험을 건너뛰거나 끄지 않는다.
- "완료"는 실제로 실행해 본 것에만 쓴다. 못 한 것은 못 했다고 적는다.
