# 협업 운영 지침: 대표 · GPT · Claude Code v1.1

- 작성일: 2026-11-14 (대표 지시 원문을 그대로 정리)
- 성격: 기존 개발 방향을 보완하는 운영 지침. `00_공통규칙서.md`와 확정된 신학·저작권·아동 보호 원칙을 바꾸지 않는다. 충돌하면 공통규칙서가 우선한다.
- 참조: `05_본제작_지시서.md` 1절의 읽을 문서 목록에 이 문서를 넣었다.

## 1. 역할

| 누가 | 하는 일 |
|---|---|
| 대표 (최종 의사결정자) | 게임의 방향, 그래픽 수준, 재미, 제작비 승인. 주요 장면과 캐릭터의 최종 품질 승인. 결과를 직접 확인하고 수정 여부를 정한다 |
| GPT (총괄 기획·분석·품질 검증) | 전체 구조와 기술 방향 분석, 기존 방식의 문제와 개선책 검토, 지시서와 우선순위 검토, 3D 그래픽 품질·사용자 경험·게임 구성 평가, Claude Code의 결과와 실제 증거 비교, 필요하면 수정 지시서 작성. **실제로 검토하지 않은 항목을 GPT 검증 완료로 표시하지 않는다** |
| Claude Code (개발·구현·테스트) | Three.js, Blender 등으로 개발. 캐릭터, 배경, 애니메이션, 특수효과 구현. 실제 실행, 자동 테스트, 오류 수정. 작업 기록 정리. GPT가 검토할 수 있는 코드와 결과물 제공. 설계 개선안을 적극 제안하되, 확정된 기획이나 주요 제작 방식을 바꾸려면 대표의 승인을 받는다 |
| Codex (2차 코드 검토, 2026-11-14 추가) | 필요할 때만 수동으로 불러 특정 기능의 코드를 읽기 전용으로 검토한다. 고치지 않는다. 지적은 Claude Code가 재검증하고, 수정은 대표 승인 뒤 Claude Code가 한다(9절) |

## 2. 검증의 다섯 갈래

코드가 정상 실행되는 것과 게임의 품질이 좋은 것은 별개다. 다섯 가지를 따로 검증하고 따로 보고한다.

| 갈래 | 내용 | 누가 확인할 수 있나 |
|---|---|---|
| 1. 기술 | 실행, 오류, 코드 구조 | Claude Code (자동 점검) |
| 2. 기능 | 이동, 충돌, 카메라, 게임 진행 | Claude Code (자동 점검, 휴대폰 크기 화면) |
| 3. 그래픽 | 모델링, 조명, 재질, 애니메이션, 장면 완성도 | 실제 렌더링 화면으로. 최종은 대표 |
| 4. 사용자 경험 | 어린이의 이해도, 조작 편의성, 재미 | 실제 어린이 테스트. 하지 않았으면 미검증 |
| 5. 성경적 정확성 | 본문 일치, 목회자 감수 | 별도 검증자 대조 + 목회자. 감수 전이면 미검증 |

- 자동 테스트를 통과했어도 그래픽 품질이 부족하면 최종 완성으로 보고하지 않는다.
- 어린이 테스트나 목회자 감수를 하지 않았으면 그 항목은 미검증으로 적는다.

## 3. 협업 절차

1. **작업 시작 전**: Claude Code가 지시서를 확인하고 진행할 작업, 구현 방법, 예상되는 기술적 한계, 검증 기준을 정리한다. 중요한 기술 선택이나 방향 변경이 필요하면 대표가 GPT에 전달할 수 있게 자료를 낸다.
2. **개발과 자체 테스트**: Claude Code가 코드를 쓰고 게임을 실행한다. 가능하면 브라우저에서 직접 조작하고 스크린샷과 테스트 결과를 남긴다.
3. **GPT 외부 검토**: 대표가 필요하다고 판단한 단계에서 결과를 GPT에 전달한다. Claude Code는 다음을 준비한다: 작업 내용과 변경 파일, 실제 게임 스크린샷, 주요 코드와 실행 방법, 자동 테스트 결과, 해결하지 못한 문제, 기술적 한계.
4. **수정과 재검증**: 대표가 GPT 의견을 전하면 Claude Code가 분석한다. 타당하면 반영하고, 어렵거나 기존 규칙과 충돌하면 근거와 대안을 설명한다. 고친 뒤 다시 실행하고 검증한다. GPT의 제안을 무조건 따르지도, 기존 판단을 무조건 유지하지도 않는다. 검증 가능한 결과와 근거로 판단한다.

## 4. 그래픽 제작 특별 원칙

- 원통, 구, 상자 같은 기본 도형을 조합한 인물이 대표가 원하는 품질에 도달했는지 엄격하게 평가한다.
- Blender에서 만들었다는 이유만으로 고품질이라고 판단하지 않는다.
- 기본 도형 방식에 한계가 있으면 제작 기술의 변경을 제안한다. 외부 3D 모델, AI 모델 생성 도구, GLB 에셋 등을 비교할 수 있다.
- 새 제작 방식은 적용하기 전에 캐릭터 한 명으로 시험한다(지금: `07_인물품질_개선실험_계획.md`).
- 기존 조작 기능과 진행 상태를 보존한다.
- 평소에는 인형풍, 압도적인 성경 장면에서만 사실적이고 황홀한 연출을 쓰는 기존 방향(지시서 6절)을 유지한다.
- 그래픽 품질이 개선됐는지는 실제 렌더링 화면으로 판단한다.
- 대표가 승인하지 않은 유료 결제는 하지 않는다.

## 5. 작업 종료 보고 형식

주요 작업이 끝나면 아래 형식으로 보고한다. 각 항목은 **완료 / 부분 완료 / 미검증**으로 구분한다. 기술 테스트 통과를 전체 품질 검증 통과로 표현하지 않는다.

```
3. 실제 실행 및 자동 테스트 결과
4. 그래픽 품질 평가와 스크린샷
5. 남아 있는 오류와 품질 문제
6. GPT 검토가 필요한 사항
7. 대표가 결정하거나 승인해야 하는 사항
8. 다음 작업 제안
```

- 대표의 개인 운영 원칙(결과물 맨 위의 결재 카드: 위험도, 정할 것, 검증 한 줄)과 함께 쓴다. 결재 카드를 맨 위에 두고 그 아래에 이 8항목을 붙인다.

## 6. 기록 원칙

- `00_공통규칙서.md`와 `05_본제작_지시서.md`를 존중한다. 기존 승인 사항을 임의로 삭제하거나 덮어쓰지 않는다.
- GPT의 검토 의견은 **대표가 전달한 실제 내용만** 아래 7절에 기록한다. GPT가 저장소를 확인하지 않았는데 확인했다고 쓰거나, 대표가 승인하지 않은 사항을 승인 완료로 쓰지 않는다.

## 9. Codex 2차 검토 (2026-11-14 대표 승인)

OpenAI Codex는 **필요할 때만 수동으로 부르는 독립 2차 검토자**다. 개발은 계속 Claude Code가 맡는다. 실행 방법은 `tools/codex_review/README.md`에 있다.

| 규칙 | 내용 |
|---|---|
| 역할 | 코드 읽기 전용 검토만 한다. 수정, 패치, 리팩터링, 커밋, 설정 변경은 하지 않는다. `/codex:rescue`, `--write`, 승인 우회·전체 접근 옵션은 쓰지 않는다 |
| 부르는 때 | 대표나 Claude가 필요하다고 판단한 기능 단위로 1회씩. 자동 리뷰 게이트와 자동 반복은 쓰지 않는다 |
| 격리 | 저장소 복사본을 읽기 전용으로 마운트하고, 원본·인증 경로는 숨긴다. `nobody` 사용자, 최소 환경 변수, Codex 샌드박스 `read-only`로 실행한다. 매번 새 세션을 쓴다. 실행 전 격리 시험(`pretest.sh`)을 통과해야 한다 |
| 검증 | 지시에 파일·줄 범위를 적는다. Codex 세션 기록에서 실제 적용된 샌드박스 값과 읽은 범위를 확인한다. 원본·복사본 지문을 전후로 비교한다. 지적은 Claude가 하나씩 재검증한다. 허위 지적, 권한 위반, 호출 실패는 따로 센다 |
| 수정 | 재검증으로 확인된 지적만, 대표 승인 뒤에 Claude가 고친다. 두 AI가 같은 파일을 동시에 고치지 않는다 |
| 인증·비용 | ChatGPT 계정 장치 코드 로그인(새 작업 환경마다 1회, 대표가 코드 입력). 인증 정보는 작업 환경의 Codex 전용 홈에만 둔다. API 키 과금으로 바꾸지 않는다. 호출마다 요금제 사용량(5시간·주간 %)을 기록한다 |
| 그만둘 때 | Codex를 쓰지 않아도 Claude 단독 + GPT 검증 방식은 그대로 돌아간다 |

### 첫 실험 결과 (2026-11-14, 모세 GLB 불러오기와 Idle·HideFace 연결)
- 격리 시험 네 겹 모두 통과했다. Codex 샌드박스는 복사본, `/tmp`, Codex 홈 쓰기를 모두 `Read-only file system`으로 막았고, 외부 접속도 막았다.
- 리뷰는 77초 걸렸다. 지적 2건, 문제없음 확인 7항목. 허위 지적 0건, 권한 위반 0건, 호출 실패 1건(입력 대기로 멈춤, 모델 호출 전, `< /dev/null`로 해결). 원본과 복사본 모두 바뀌지 않았다.
- 지적 B-1(늦은 로딩 때 자세 유실, Codex 판정 '중간'): 코드상 맞다. 다만 실측해 보니 GLB 교체가 페이지 시작 0.7초 뒤(CPU 6배 느리게 해도 2.6초)에 끝나 실제로는 일어나지 않는다. '낮음'으로 정정하고 수정하지 않았다.
- 지적 B-2(시작 화면에서 Idle이 적용되지 않음, '낮음'): 브라우저에서 확인했다. 대표 승인 뒤 `web3d/js/game.js` 1줄을 고쳤다(교체 직후 `mixer.update(0)`).
- 사용량: 모델 호출 3회, 5시간 한도 1%, 주간 0%, 추가 결제 없음. 로그인은 코드 표시부터 성공까지 14분 19초 걸렸다(문답 대기 포함, 순수 입력 시간은 미측정).
- 바깥 흔적: OpenAI 쪽 사용·대화 기록과 ChatGPT 계정의 로그인 기기 기록은 여기서 지울 수 없다(대표가 ChatGPT 설정에서 처리).
