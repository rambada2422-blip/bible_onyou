## 2. 대표가 "받아 줘"라고 할 때 총괄이 하는 순서

1. `git fetch origin` 뒤 일곱 줄의 브랜치를 모두 본다 (`relay/horeb`, `relay/tools`, `relay/web2d`, `relay/docs`, `gpt/sian-horeb`, `gpt/sian-jordan`, `gpt/sian-next`). 줄마다 `git log main..origin/브랜치`와 `git diff --stat main...origin/브랜치`로 새로 올라온 것과 바뀐 파일을 본다.
2. 인계 파일(`docs/인계/`)의 첫 줄이 `상태: 끝`인 단계만 받는다. `하는 중`이면 받지 않고 그대로 둔다.
3. 코드: 다른 AI가 쓴 코드는 읽지 않는다. 대신
   - 따로 만든 작업 폴더에서 돌린다: `git worktree add --detach /home/user/bo_relay origin/브랜치` 뒤 `git merge --no-edit main` (합친 뒤의 모습으로 본다), `node tools/check.js --full` (15분쯤. 백그라운드로 돌린다).
   - 바뀐 파일이 일감의 '건드릴 파일' 안인지 본다.
   - 내용 파일(`content.js`, `content3d.js`)이 바뀌었으면 승인된 문서의 자료와 글자 그대로 같은지 기계로 대조한다.
   - 화면 사진(`docs/인계/사진/`과 `dist/check/` 아래)을 직접 열어 본다.
4. 그림: 원본을 직접 열어 보고, 고친 곳은 앞 판과 나란히 2배 넘게 확대해 본다. **만든 쪽의 기록을 보지 않은 별도 검증자(서브에이전트)에게 그림만 주고 흠을 찾게 한다.** 금지 사항은 진행판 '작업 카드 E'의 여섯 줄, 지시서 6.2절, 그림 스타일 가이드 2절이다. 검증자의 지적은 총괄이 다시 확대해 맞는지 본 뒤에 쓴다.
5. 검토 문서(그림은 그 시안 폴더의 `총괄_검토.md`)와 진행판의 작업 기록을 쓰고 main에 올린다 (문서만. 받은 브랜치는 아직 합치지 않는다).
6. 대표에게 사진을 보내고 예/아니오로 묻는다 (합칠지, 그림을 고를지). **대표의 허락 없이 받은 브랜치를 main에 합치지 않는다.**
7. 허락을 받으면: 그사이 브랜치가 더 나아갔어도 **대표가 승인한 커밋까지만** `git merge --no-ff 커밋번호`로 합친다. 합친 뒤의 코드가 점검받은 것과 같은지 `git diff --stat`으로 본다. 빠른 점검을 돌리고, `git fetch origin main`으로 원격 main이 그대로인지 본 뒤 `git push origin main`.
8. 작업 줄 문서의 표(끝남, 다음 차례, 문), 진행판(▶ 다음, 열린 브랜치, 상태판, 작업 기록)을 고친다.
