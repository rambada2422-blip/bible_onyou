# 진행판

어느 AI, 어느 계정, 어느 컴퓨터에서 열어도 이 파일 하나로 이어받는다. 위쪽 '지금 상태'는 고쳐 쓰고, 맨 아래 '작업 기록'은 지우지 않고 맨 위에 새 기록을 더한다. 이 파일은 총괄만 고친다. 다른 세션은 `docs/인계/`에 인계 파일을 쓴다.

## 지금 상태

▶ 다음: 분산 1차. 대표가 아래 '계정마다 붙여 넣을 첫 지시'를 GPT, Gemini, Claude 2.9만 원 계정에 넣는다. 총괄(Claude 29만 원)은 카드 D를 끝냈다. 카드 A가 끝났다는 브랜치 이름이 오면 합치고, 카드 1과 카드 B의 '건드릴 파일'을 적어 2차를 배정한다.

| 칸 | 내용 |
|---|---|
| 목표 | 출애굽기 시범판 본 제작. 호렙 산 한 장면에서 지시서 4절 1~4번을 끝내고 대표에게 보여 준다 |
| 총괄 | Claude 29만 원 계정. 배정표와 이 진행판은 총괄만 고친다 |
| 열린 브랜치 | `claude/happy-gates-c6c9yc` (카드 D 문서와 카드 1, 4-나. main에 합치기 전) |
| 대표 답이 필요한 것 | 지시서 3.3절 표 참고 |

### 배정표

계정마다 한 줄이다. 자기 줄의 '지금 맡은 일'만 한다. 일이 끝나면 총괄이 이 표를 고쳐 다음 일을 준다.

| 계정 | 지금 맡은 일 (1차) | 브랜치 | 그다음 (2차) |
|---|---|---|---|
| Claude 29만 원 (총괄) | 합치기와 배정. 카드 D는 끝냈다 | 환경이 정해 준 이름 (지금 `claude/happy-gates-c6c9yc`) | 2번 압도 장면 (만드는 방법은 대표 승인 뒤) |
| GPT 2.9만 원 | 카드 A (`game.js` 나누기) | 새 브랜치 (예: `gpt/card-a`) | 카드 1, 이어서 카드 4-나 |
| Gemini 2.9만 원 | 안내 문서를 읽는지 확인만 하고 기다린다. 남은 코드 일이 모두 카드 A와 같은 파일을 고쳐서 지금 맡길 일이 없다 | 없음 | 카드 B (카드 A가 main에 합쳐진 뒤) |
| Claude 2.9만 원 | 카드 C (`alt02.svg` 다시 그리기) | 새 브랜치 (환경이 정해 준 이름 그대로) | 4-나가 끝난 뒤 화면에 들어간 물음을 `docs/07_호렙_퀴즈와_동선.md`와 대조 |

2차는 카드 A가 main에 합쳐진 뒤에 시작한다. 그때 총괄이 나뉜 파일 이름으로 카드 1과 카드 B의 '건드릴 파일'을 다시 적고 이 배정표를 고친다. 겹치는 파일이 없을 때만 둘을 동시에 하고, 겹치면 카드 B를 먼저 합친 뒤 카드 1을 시작한다. 대표는 총괄이 "배정표를 고쳤다"고 말한 뒤에만 2차 지시를 붙여 넣는다.

### 작업 카드 A · `game.js` 나누기

- 왜: `web3d/js/game.js`가 1,102줄, 72KB로 한 파일에 몰려 있다. 고칠 때마다 통째로 읽게 되어 모든 AI의 사용량이 늘어난다.
- 할 일: 역할별로 여러 파일로 나눈다 (예: 조작, 카메라, 진행, 화면 안내, 점검용 `BO3D.debug`). 나눈 파일은 `web3d/js/` 아래에 둔다.
- 건드릴 파일: `web3d/js/game.js`와 거기서 나온 새 파일, `web3d/index.html`의 script 줄, `tools/build3d.js`의 `scripts` 목록.
- 하지 말 것: 동작, 문구, 숫자를 바꾸지 않는다. 옮기기만 한다. `content.js`, `content3d.js`, `models*.js`는 건드리지 않는다.
- 완료 기준: 나눈 파일이 각각 400줄 이하. `node tools/check.js --full` 합격.

### 작업 카드 B · 양 떼 30마리 이상 (지시서 4절 3번)

- 할 일: 모세가 이끄는 양 떼를 30마리 이상으로 늘리고 무리 지어 움직이게 한다. 지금은 7마리이고 `game.js`의 `var sheep = []` 부분에서 `P.flock` 둘레에 놓는다 (카드 A 뒤에는 나뉜 파일에 있다). 양 모델은 `models.js`의 `makeSheep`이다.
- 건드릴 파일: 양 떼를 놓고 움직이는 코드가 든 파일, `BO3D.debug`가 든 파일 (양의 수 값 한 줄만), `web3d/js/models.js`의 `makeSheep`, `tools/test/walk3d.js` (양의 수를 확인하는 줄만).
- 자리: 양 떼는 `P.flock` 가운데에서 9 안쪽에 퍼진다. 언덕(떨기나무에서 15 안쪽)에는 오르지 않는다 (`docs/07_호렙_퀴즈와_동선.md` 4.1절).
- 완료 기준: `BO3D.debug`에 양의 수를 알려 주는 값을 더하고, `walk3d.js`가 30 이상인지 확인해 아니면 실패하게 한다. `node tools/check.js --full` 합격. 양 떼가 보이는 화면 사진 한 장을 `docs/인계/사진/카드B.png`로 복사해 함께 커밋한다.
- 대표 확인: 실제 휴대폰에서 끊기지 않는지는 대표가 링크를 열어 확인한다.
- 지킬 것: 양 떼는 출 3:1의 배경이다. 본문에 없는 사건을 더하지 않는다.

### 작업 카드 C · `alt02.svg` 다시 그리기 (지시서 4절 5번)

- 왜: 2D 시범판의 요단 강 그림이 3D 설정과 다르다. 멈춰 쌓인 물을 건너는 곳 바로 옆에 그렸고 좌우 방향도 확인하지 않았다 (장면목록 3절 'ALT-02의 3D 장면 설정' 아래 '고쳐야 할 것').
- 할 일: `tools/art-src/gen_alt02.js`를 고쳐 그림을 다시 만든다. 장면목록의 'ALT-02의 3D 장면 설정' 표 다섯 항목(방향, 쌓인 물, 백성과 궤의 거리, 궤, 지도자)과 하나씩 맞춘다.
- 건드릴 파일: `tools/art-src/gen_alt02.js`, `web/assets/bg/alt02.svg`, `web/assets/bg/alt02.meta.json`. `web3d/` 아래 파일은 읽기만 한다.
- 쌓인 물: 그리지 않는다. 그림 영역 `water`는 이름을 그대로 두고 물이 끊어져 드러난 강바닥 자리로 옮긴다. 그러면 `web/js/content.js`는 고칠 필요가 없다. 영역 이름을 꼭 바꿔야 하면 `content.js`에서 그 이름을 쓰는 두 곳의 이름만 바꾼다.
- 아이에게 보이는 문구는 고치지 않는다. 새 그림과 어긋나는 문구를 찾으면 인계 파일에 적어 총괄에게 넘긴다.
- 목회자 판단이 필요하다고 적힌 설정은 장면목록에 적힌 값(제사장 넷, 흰 세마포, 백성은 하류 쪽으로 건넘)을 그대로 그린다. 값이 적혀 있지 않은 것(지도자가 선 자리)은 지금 그림의 자리를 그대로 둔다. 바꿔야 할 것 같으면 그리지 않고 인계 파일에 적는다.
- 하지 말 것: 금빛 궤를 드러내지 않는다. 지도자가 강을 가리키거나 손을 내밀게 그리지 않는다.
- 완료 기준: 표 다섯 항목과 그림을 하나씩 대조한 표가 인계 파일에 있다. 다시 그린 그림의 화면 사진을 열어 봤고, 한 장을 `docs/인계/사진/카드C.png`로 복사해 함께 커밋했다. `node tools/check.js --full` 합격.

### 작업 카드 D · 호렙 산 퀴즈와 동선 설계 (지시서 4절 4번의 글, 1번의 설계) · 총괄 · 끝

- 왜: 부품 찾기를 성경 퀴즈와 묶고 (지시서 3.1의 3번), 부품을 줍고 나면 언덕 위의 떨기나무를 올려다보게 한다 (3.1의 4번). 부품 자리와 물음은 성경 근거를 따져야 해서 Claude가 쓴다.
- 할 일: 새 문서 `docs/07_호렙_퀴즈와_동선.md` 한 개를 쓴다. 코드 파일은 건드리지 않는다.
  - 부품 세 개마다: 근거 장절, 나이 단계별 물음과 보기 (보기마다 근거 장절 또는 "본문에 없음"), 정답 근거, 답이 알려 주는 다음 찾을 곳.
  - 지형과 동선: 언덕과 떨기나무의 자리, 부품 세 개의 자리, 아이들이 올려다보는 자리, 양 떼의 자리. 규칙서 3.3과 지시서 6.2를 지킨다.
  - 이 문서를 바탕으로 카드 1 (지형과 동선 구현)과 4-나 (퀴즈를 화면에 넣기)의 카드를 이 진행판에 쓴다.
- 완료 기준: 규칙서 8절의 필수 항목이 물음마다 다 있다. 작성 과정을 보지 않은 별도 검증을 거쳐 지적을 반영했다. 카드 1과 4-나의 '건드릴 파일'은 카드 A가 합쳐진 뒤 나뉜 파일 이름으로 적는다.

### 작업 카드 4-나 · 탐지기 물음을 화면에 넣기 (지시서 4절 4번)

- 왜: 탐지기만 보고 찾는 것이 아니라 성경 퀴즈를 풀면서 부품을 찾게 한다 (지시서 3.1의 3번).
- 할 일: `docs/07_호렙_퀴즈와_동선.md` 1절 흐름대로 바꾼다. 문서 5절 자료를 `web3d/js/content3d.js`에 그대로 붙여 넣고, 화면은 그 자료에서 문구를 읽어 쓴다. 문서 2절 '세 물음에 함께 쓰는 것'과 3절을 따른다.
- 건드릴 파일: `web3d/js/content3d.js` (5절 자료 붙여 넣기만), 진행 흐름과 화면 안내가 든 파일 (카드 A 뒤에 총괄이 이름을 적는다), `tools/test/walk3d.js`.
- 하지 말 것: 문구를 한 글자도 바꾸지 않는다. 고쳐야 할 것 같으면 고치지 않고 인계 파일에 적는다. `content.js`와 `models*.js`를 건드리지 않는다.
- 완료 기준: `walk3d.js`가 나이 단계 셋 모두에서 물음 세 개를 풀고 끝까지 간다. 맞지 않는 보기를 한 번 고른 뒤 다시 고르는 것도 확인한다. 물음 화면 사진 한 장을 `docs/인계/사진/카드4나.png`로 복사해 함께 커밋한다. `node tools/check.js --full` 합격.
- 뒤이어: `content3d.js`가 바뀌므로 총괄이 문구를 문서와 대조한다.

### 실패·주의

- 지시서 5절 '이전 세션에서 배운 것'을 먼저 읽는다.
- 브랜치에만 있고 main에 합쳐지지 않은 작업은 다른 계정에서 보이지 않는다.
- 전체 점검은 화면 없는 환경에서 10~25분 걸린다. 백그라운드로 돌린다.
- GPT(Codex)와 Gemini가 `AGENTS.md`를 실제로 읽는지는 아직 시험하지 않았다. 아래 지시의 둘째 줄이 그 확인이다. 맞는 답은 "코드 구현과 정리 (결과가 자동 점검으로 확인되는 일) | GPT(Codex), Gemini가 먼저 맡는다. 둘 다 못 할 때만 Claude | `node tools/check.js --full` 합격"이다. 다르면 일을 시키지 않고 대표가 총괄에게 알린다.
- 카드 1과 카드 4-나의 '건드릴 파일'에는 아직 이름을 못 적은 파일이 있다. 카드 A가 합쳐지면 총괄이 나뉜 파일 이름으로 적는다. 그 전에는 시작하지 않는다.

### 계정마다 붙여 넣을 첫 지시

```

먼저 AGENTS.md의 업무 분담 표에서 '코드 구현과 정리'로 시작하는 줄을 그대로 말해 줘.

- 커밋하고 푸시한 뒤 브랜치 이름을 나에게 알려 준다. main에는 합치지 않는다. 합치기는 총괄이 한다.
```

Gemini 2.9만 원:

