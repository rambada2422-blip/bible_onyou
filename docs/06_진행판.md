### 작업 카드 A · `game.js` 나누기

- 왜: `web3d/js/game.js`가 1,102줄, 72KB로 한 파일에 몰려 있다. 고칠 때마다 통째로 읽게 되어 모든 AI의 사용량이 늘어난다.
- 할 일: 역할별로 여러 파일로 나눈다 (예: 조작, 카메라, 진행, 화면 안내, 점검용 `BO3D.debug`). 나눈 파일은 `web3d/js/` 아래에 둔다.
- 건드릴 파일: `web3d/js/game.js`와 거기서 나온 새 파일, `web3d/index.html`의 script 줄, `tools/build3d.js`의 `scripts` 목록.
- 하지 말 것: 동작, 문구, 숫자를 바꾸지 않는다. 옮기기만 한다. `content.js`, `content3d.js`, `models*.js`는 건드리지 않는다.
- 완료 기준: 나눈 파일이 각각 400줄 이하. `node tools/check.js --full` 합격.

### 작업 카드 B · 양 떼 30마리 이상 (지시서 4절 3번)

- 할 일: 모세가 이끄는 양 떼를 30마리 이상으로 늘리고 무리 지어 움직이게 한다. 지금은 7마리이고 `game.js`의 `var sheep = []` 부분에서 `P.flock` 둘레에 놓는다 (카드 A 뒤에는 나뉜 파일에 있다). 양 모델은 `models.js`의 `makeSheep`이다.
- 건드릴 파일: 양 떼를 놓고 움직이는 코드, `models.js`의 `makeSheep`, `tools/test/walk3d.js`.
- 완료 기준: `BO3D.debug`에 양의 수를 알려 주는 값을 더하고, `walk3d.js`가 30 이상인지 확인해 아니면 실패하게 한다. `node tools/check.js --full` 합격. 양 떼가 보이는 화면 사진이 `dist/check/horeb/`에 남는다.
- 대표 확인: 실제 휴대폰에서 끊기지 않는지는 대표가 링크를 열어 확인한다.
- 지킬 것: 양 떼는 출 3:1의 배경이다. 본문에 없는 사건을 더하지 않는다.

### 실패·주의

- 지시서 5절 '이전 세션에서 배운 것'을 먼저 읽는다.
- 브랜치에만 있고 main에 합쳐지지 않은 작업은 다른 계정에서 보이지 않는다.
- 전체 점검은 화면 없는 환경에서 10~25분 걸린다. 백그라운드로 돌린다.
- GPT(Codex)와 Gemini가 `AGENTS.md`를 실제로 읽는지는 아직 시험하지 않았다. 첫 세션에서 "AGENTS.md의 업무 분담 표 첫 줄을 그대로 말해 줘"로 확인한다.
