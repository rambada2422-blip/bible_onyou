# 갈래 verify: 40장면 내용 3차 전수 대조 (앞의 두 번과 다른 방법으로)

먼저 `00_공통지시.md`를 읽는다. 브랜치는 `claude/auto-verify`.

## 목표
이 게임에서 가장 큰 사고는 **성경과 다른 내용이 아이에게 나가는 것**이다. 지금까지 독립 대조를 두 차례 했고 그때마다 높음 지적이 나왔다. 목회자 감수 전에, 앞의 두 번과 **다른 방법으로** 한 번 더 전수 대조해 목회자가 볼 양을 줄인다.

## 방법
1. **기계 검사를 먼저 넓힌다**(`tools/validate_ot.js`에 `--v4`로 더한다. 기존 플래그의 결과는 바꾸지 않는다). 예: 적힌 모든 장절이 실제로 있는 장·절인가(`tools/bible_ref/`), 정답 근거 장절이 그 장면의 본문 범위 안인가, 보기마다 근거 장절이나 "본문에 없음" 표시가 있는가, 장절 표기 형식이 한 가지인가, 같은 물음의 세 나이 단계가 서로 다른 사실을 말하지 않는가(숫자·이름·순서를 뽑아 견준다), 본문과 10글자 이상 그대로 겹치는 곳이 없는가. 검사가 잡은 것은 사람이 읽고 진짜인지 가린다.
2. **읽는 대조**: 시대 2개씩 맡은 에이전트 5명(동시에 4명까지)이 `_verify/`의 앞선 기록과 작성 과정을 **보지 않고**, 장면 자료와 본문만으로 틀린 곳을 찾는다. 찾을 것: 사실이 본문과 다름 / 본문이 말하지 않는 것을 단정함 / 정답이 본문과 다름 / 오답으로 둔 보기가 사실은 본문에 맞음 / 장절이 그 내용을 담고 있지 않음 / 나이 단계 사이의 사실 불일치 / 인물이 본문에 없는 말·행동·속마음 / 순서 맞추기·잇기 물음의 정답 순서와 짝. 대상: 대목 글, 관문 240, 3D 탐지기 물음 108, 현장 돕기 120단계와 손으로 하는 돕기 42단계, 오늘의 물음, 말씀 카드, 시대 안내(`eras.json`).
3. **반박 검증**: 지적마다 다른 에이전트가 "이 지적이 틀렸다"는 쪽에서 본문으로 따져 본다. 살아남은 것만 고친다. 신학 판단이 걸린 것(뜻·적용·신약 연결)은 고치지 않고 "감수 항목"으로 넘긴다.
4. 고친 뒤: `validate_ot.js` 모든 플래그 오류 0, `node tools/build_ot.js`, `node tools/build3d.js`, `walkOT.js` 3단계 40/40.
5. 기록: `content/ot/_verify/era-N.md`에 "3차 전수 대조 (자동 작업, 2026-11-16~17)" 절을 **더한다**(지적 번호, 높음·중간·낮음, 고침/감수로 넘김/기각과 까닭).

## 네 파일
`content/ot/OT-*.json`의 글과 물음(3D 갈래가 만지는 `design3d`는 고치지 않는다), `content/ot/eras.json`, `content/ot/_verify/era-N.md`(더하기만), `tools/validate_ot.js`, `tools/bible_ref/`. `content/ot/작성규칙.md`는 읽기만 한다(규칙이 모자라면 "대표 결정 대기"에 적는다).

## 여력이 남으면
- 2D 시범판 `web/js/content.js`(출애굽 13장면)와 `web3d/js/content3d.js`를 같은 방법으로 대조한다(이 두 파일은 네 것이다).
- 영어 KJV(`ref/bible/en_kjv.json`)와 견주어 개역한글만으로는 놓치기 쉬운 숫자·이름·순서를 다시 본다.
- 저장소에 자동 검사를 건다: `.github/workflows/check.yml`(푸시 때 `validate_ot.js` 모든 플래그와 `build3d.js`). 권한 때문에 푸시가 거절되면 파일을 `docs/auto/`에 두고 진행 파일에 적는다.
- 8~10세 글을 소리 내어 읽었을 때(읽어 주기) 어색한 문장, 어려운 낱말 목록(고치지는 말고 목록만. 글을 고치면 다시 대조해야 한다).
