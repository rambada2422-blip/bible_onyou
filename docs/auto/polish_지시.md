# 갈래 polish: 이미 있는 3D 12장면을 휴대폰에서 가볍게, 낮은 지적 고치기

먼저 `00_공통지시.md`를 읽는다. 브랜치는 `claude/auto-polish`.

## 목표
1. **휴대폰에서 가볍게.** 진행표의 "장면 무게"를 보면 기드온 지켜보기는 그리기 호출 약 1,040회(호렙 산의 2.8배)이고, 실제 휴대폰에서는 재 본 적이 없다. 모든 3D 장면(호렙 산 + 11장면)의 그리기 호출·삼각형·초당 장면 수를 `tools/test/perf3d.js`로 **먼저 재서 표로 남기고**, 화면이 달라지지 않는 방법(같은 모양 한 번에 그리기, 움직이지 않는 것 합치기, 그림자 범위 줄이기, 먼 것 단순하게)으로 줄인다. 목표: 모든 장면의 그리기 호출이 호렙 산(377회) 수준 이하, 삼각형은 지금보다 늘지 않음. 고치기 전·후 화면을 같은 자리에서 찍어 직접 비교한다(달라졌으면 되돌린다).
2. **느린 휴대폰 자동 대응.** 초당 장면 수가 낮으면 그림자·화면 배율·먼 거리의 무리를 스스로 낮추는 장치(이미 있으면 범위를 넓히고, 없으면 만든다). 움직임 줄이기 설정은 그대로 따른다.
3. **진행표의 "남은 낮은 지적" 6가지**를 고친다(여리고의 진으로 돌아가는 모습 수 6:11·6:14 / 엘라의 돌 고르는 동작과 사람들의 자리 / 홍해 구름 기둥의 양쪽 빛 출 14:20 / 아브람 장면의 사건 뒤 시간과 모레 나무 / 화면 위 장절 표시가 대목의 장절을 따라가게 / 재료 대목의 긴 글). 고친 배치는 작성 과정을 보지 않은 에이전트가 본문과 대조한다. 본문이 말하지 않는 것은 그리지 않는 쪽으로.
4. 고친 뒤 `walk3d.js` 3단계, `walk3dScene.js` 11장면 × 3단계, `walkJ.js`가 모두 통과해야 한다.

## 네 파일
`web3d/js/scene_*.js`(지금 있는 12개), `models.js`, `models_jordan.js`, `props_ot.js`, `world.js`, `flock.js`, `jordan.js`, `game.js` 가운데 그리기·성능·카메라·장절 표시 부분, `tools/test/perf3d.js`, `walk3d.js`, `walk3dScene.js`, `walkJ.js`. `game.js`의 화면 글·보상·아지트 부분과 `ui.js`·`story.js`·`fx.js`·CSS는 play 갈래의 것이다(재료 대목 긴 글이 CSS 문제면 "다른 갈래·총괄에 부탁"에 적는다).

## 여력이 남으면
- 미리보기 한 파일의 크기와 첫 화면까지 걸리는 시간을 재고 줄인다(GLB 무게, 쓰지 않는 코드).
- 조작감: 한 손 조작, 카메라가 지형·벽에 묻히는 곳, 걷다가 끼이는 곳을 자동 걷기로 찾아 고친다.
- 장면마다 "사진 찍기 좋은 자리" 점검(도감용 화면이 본문과 어긋나지 않는지).
