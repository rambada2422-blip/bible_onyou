## 점검 결과 읽기

`node tools/check.js`는 문법, 2D·3D 미리보기 묶기, 바뀐 파일을 확인하는 빠른 점검이다. `node tools/check.js --full`은 여기에 아래 표의 2D 시범판, 사진형 배경, 3D 호렙 산, 3D 요단 강을 더한다. 압도 장면 배치는 별도 명령으로 실행한다. [점검 도구](../../tools/check.js)

전체 점검에서 Playwright가 없으면 자동 조작이 건너뛰어지고 마지막 줄에 `합격 (확인 필요 …건)`이 나올 수 있다. 자동 조작의 통과는 해당 줄에서 확인한다. 전체 점검은 각 실행의 종료 코드가 0이고 출력에 `no errors`가 있으며 `ERR` 또는 `FAIL` 표시가 없을 때 그 항목을 통과 처리한다. 미리보기와 조작 사진은 `dist/`와 `dist/check/`에 생성된다.

## 자동 조작별 순서와 확인 항목

| 자동 조작 | 무엇을 누르거나 하는가 | 무엇을 확인하는가 |
|---|---|---|
| **2D 시범판**. 전체 점검에서는 11~13세 한 단계, 목적지 ‘모세’, 390×844. [walk2d.js](../../tools/test/walk2d.js) | ① 탐험 시작 → 나이 선택 → 출발 준비 완료. ② 애굽의 종살이 장면 → 다음 목적지에서 모세 → 떨기나무 → 낮·밤 기둥. ③ 관문에 따라 보기를 누르거나, 찾았다고 누르고 답하거나, 순서·장절·여러 보기·그림의 단서를 조작한다. 처음 만난 선택형에서 맞지 않는 보기도 한 번 누른다. 장절형을 만났을 때 잘못된 값과 맞는 값을 차례로 넣는다. ④ 돌아와 일지와 구성 안내를 연다. | 필요한 화면과 버튼이 나타나고 장면과 관문을 따라 진행할 수 있는지 본다. 장면이 지정된 횟수 안에 끝나지 않거나 필요한 관문을 찾지 못하면 실패한다. 장면·답변·일지 등의 사진과 브라우저 오류를 남긴다. 정답·순서는 게임이 읽는 자료를 이용한다. 별도 실행에서 여호수아나 요셉을 인자로 주면 고른 우회 장면을 거친다. |
| **사진형 배경**, 390×520의 가상 화면에서 사진 표시. [bgraster.js](../../tools/test/bgraster.js) | ① 900×1200 시험용 JPG를 만들고 2D 묶기를 실행한다. ② 묶은 그림을 화면에 띄우고 확대 2배의 사진을 찍는다. ③ 같은 키의 SVG+JPG, JPG+PNG, 한 장 300KB 초과, 900×1200이 아닌 치수, 합계 1.5MB 초과를 하나씩 만들어 다시 묶는다. ④ 시험용 파일을 지우고 원래 그림을 다시 묶는다. | JPG가 불러와지고 실제 화면 폭이 양수이며 사진 가운데가 지정한 빨강인지 검사한다. 네 귀퉁이의 색도 읽는다. 합격 판정의 색 비교에는 가운데만 쓴다. 잘못된 입력 다섯 경우에서 묶기가 실패하고 청소 뒤 `art.js`가 실행 전 내용으로 돌아오는지 검사한다. |
| **3D 호렙 산**. 390×844에서 세 나이 단계, 전체 점검은 11~13세부터 시작. [walk3d.js](../../tools/test/walk3d.js) | ① 나이를 고르고 탐험 시작 → 모세 → 도입 두 화면. ② 탐지기 물음 세 개에서 맞지 않는 보기, 이동 키, 맞는 보기 순으로 조작한다. 각각 신호를 따라 이동해 부품을 줍는다. ③ 압도 장면에서 그림 교체 전후와 부르심·얼굴 가림 글을 본다. ④ 남은 목격과 관문을 통과하고, 타임머신 안팎을 오가며 스위치도 조작한다. ⑤ 다음 시대로 출발 → 처음부터 다시 → 첫 탐지기 물음으로 돌아온다. | 아래 **호렙 산 세부 검사**에서 자료, 상태, 그림 교체의 수치 및 다시 시작 조건을 확인한다. 사진과 별도로 브라우저 오류가 없는지도 검사한다. |
| **3D 요단 강**. 전체 점검에서는 11~13세 한 단계, 390×844. [walkJ.js](../../tools/test/walkJ.js) | ① 나이 → 탐험 시작 → 여호수아 → 둘러보자. ② 강가 경계로 움직여 사진을 찍고 궤·마른 강바닥·성읍·행렬·지도자 쪽을 차례로 바라보며 촬영 버튼을 누른다. ③ 기록을 열었다 닫고 추리하기를 누른다. 첫 증거 질문에서는 맞지 않는 사진도 한 번 고른다. ④ 증거와 성경 확인에 답한 뒤 강 이름·결론·복귀 확인·보너스 카드를 거쳐 호렙 산에서 ‘출발하자’를 기다린다. | 사진 촬영과 추리 화면, 호렙 산 복귀까지 버튼 조작이 이어지는지 확인한다. 강가 경계의 위치와 각 단서 목록은 사진·상태 기록으로 남긴다. 경계 통과 여부와 단서 좌표·개수에 별도의 합격 수치를 두지 않는다. 브라우저 오류를 기록하며, 일부 리소스 불러오기 오류 문구는 제외한다. |

[awe_layout.js](../../tools/test/full/awe_layout.js) | 미리보기에서 시험용 기능으로 압도 장면을 연다. 390×844, 390×664, 360×560, 844×390으로 바꾸면서 가까이 보기와 전체 보기를 요청한다. 390×844에서는 전체 보기의 두 번째·세 번째 그림을 모두 본다. | 설계 문서의 식으로 계산한 보이는 범위와 게임의 표시 범위를 비교한다. 가로 화면에서 가까이 보기를 요청해도 전체 보기로 열리는지, 가까이 보기의 오른쪽 끝이 원본 x=703을 넘지 않는지, 전체 보기에서는 글 상자 위에 원본 y=1300까지 보이는지 검사한다. 좌표 계산 비교의 오차 한도는 1픽셀이다. 각 보기의 사진과 좌표를 남긴다. |

|---|---|

| 탐지기 물음 3개 | 제목·질문·보기·나이별 성경 안내를 비교한다. 내부용 보기 설명과 일부 나이의 장절이 정답 전에 나타나지 않는지 본다. 오답 뒤 부품이 늘거나 이동이 재개되지 않는지, 정답 뒤 안내와 신호가 나타나는지 검사한다. 8~10세는 성경 확인과 탐험대 안내가 이어지는 두 화면인지 확인한다. |
| 이동과 수집 | 차례가 오기 전 부품과 말씀 조각이 수집되지 않는지 검사한다. 두 번째 조각 전 모세 미도착, 양 30마리 이상, 떨기나무 목격 경계, 올바른 순서로 부품을 얻으면 조각·안내 화면이 나오고 세 부품이 모이는지 확인한다. 일부 위치 이동과 방향 맞추기에는 시험용 기능을 사용한다. |
| 압도 장면 | 진행 단계와 부르심·얼굴 가림 글 및 장절을 비교한다. 진행 중 조작 버튼이 숨고 종료 뒤 촬영 버튼이 돌아오는지 본다. 그림 교체 전후의 화면 사진을 비교한다. 원본 x=719 기준 왼쪽은 색 차이 16 초과 픽셀이 0개이고 평균 차이가 1.5 미만이어야 한다. 오른쪽은 차이 25 초과 픽셀이 1,000개보다 많아야 한다. 비교 범위는 사진에 보이는 그림 중 글이 놓이는 아래 150픽셀을 제외한 영역이다. |
| 마지막 화면과 재시작 | 관문 뒤 자유 탐험으로 돌아왔을 때 부품 셋이 모였는지, 다음 시대로 출발한 뒤 마지막 화면이 되는지 본다. 처음부터 다시 시작해 첫 탐지기 물음에서 부품이 0개이고 탐지기가 숨었는지 확인한다. |

## 확인하지 않는 것

- **실제 휴대폰 조작.** 브라우저의 가상 화면에서 정해진 크기, 선택 버튼, 키 입력과 시험용 이동을 쓴다. 실제 기기의 터치, 손가락으로 이동하기, 화면 회전, 기기별 속도와 발열은 별도 확인이 필요하다.
- **모든 화면 크기의 배치.** 시범판과 호렙·요단 강의 주요 경로는 390×844에서 돈다. 압도 장면 전용 스크립트의 네 화면 크기는 그 장면에 한정된다. 시스템 글자 확대나 글꼴을 못 받은 상태까지 훑는 검사는 없다.
- **소리의 청취 품질.** 귀에 들리는 크기, 음성·효과음의 겹침과 박자, 기기별 재생을 평가하지 않는다.
- **그림과 화면의 인상.** 대부분의 사진은 검토용 기록이다. 사진형 배경의 가운데 픽셀과 압도 장면의 교체 범위에는 수치 검사가 있다. 그림의 완성도, 작은 글의 읽기 쉬움, 화면에 나온 대상의 의미는 사진이나 기기에서 사람이 확인한다.
- **모든 나이·목적지·오답과 저장 복구.** 기본 전체 점검의 2D와 3D 요단 강은 11~13세 한 경로다. 호렙 산은 세 나이와 재시작을 시험하지만, 새로고침 후 저장 복구나 손상된 저장값까지 확인하는 것은 아니다.
- **내용의 성경 근거.** 자료에 있는 답으로 동작을 따라가거나 정해진 문구와 일치하는지 확인한다. 본문 대조와 목회자 감수는 별도로 진행한다.
