# 바이블 온유 GPT 총괄과 코딩 세션

대표는 이 총괄 대화에 새 요청을 적으면 된다. 총괄은 내용을 접수하고 작업 카드에 입력 자료, 변경 허용 범위, 완료를 증명할 예시를 적어 코딩 세션에 보낸다. 작업자가 다시 질문할 때는 총괄이 기존 본문·대표 결정·재현 결과를 확인해 답한다. 작품의 최종 승인은 대표가 한다.

| 담당 | 실제 업무 | 다음 담당에게 넘기는 것 |
|---|---|---|
| GPT 총괄 (현재 대화) | 접수, 우선순위, 파일 소유권 지정, 팀 간 중복 방지, 독립 재검증, 기술 승인 또는 구체적인 수정 지시 | 재현 명령, 기대 결과, 현재 커밋과 대표가 볼 검토본 |
| GPT 코딩 (하위 세션 coding) | GPT-6.2 Sol · High. 지정한 작업 브랜치에서 구현, 테스트, 오류 수정과 커밋 | 변경 파일, 재현 입력, 실제 출력, 실패한 경우와 한계 |
| 대표 | 완성본의 이야기·그림·동작을 실제로 보고 최종 승인 | 승인 또는 바꿀 장면 한 줄 |

새 카드가 들어오면 총괄은 접수 → 배정 → 기술 검수 → 수정 또는 기술 승인 → 대표 최종 판단 순으로 관리한다. 오류가 있으면 실패를 재현한 파일과 명령을 기존 코딩 세션에 돌려보낸다. 대표 결재에 같은 수정본을 여러 번 올리는 일을 줄이기 위해 기술 검수까지 총괄이 맡는다.

## 배정 카드 FILM-QA-001 · 열 재앙 영상 납품 검사

- 실제 담당은 GPT-6.2 Sol, 추론 High. 브랜치는 `gpt/film-delivery-qa`, 기준은 `3be5968`.
- 2026년 11월 22일 09:48:49~12:48:49 한국시간에 180분 접수 창을 열었다. 세 팀 원격 브랜치를 5분마다 조회하고 조회 시각·SHA·오류를 남긴다. 시작과 종료는 실측 기록으로 구분한다.
- 첫 조회에서 GPT `3be5968`, Antigravity `df2e533`, Claude `d5aec32`를 접수했다. 세 커밋에서 개별 영상 열 편과 팀 검토본 세 편을 확보했다. 접수와 작품 승인은 별도다.
- 구현 범위는 `tools/check-plague-films.js`, 새 커밋 재검수 도구 및 관련 회귀 테스트다. 다른 팀의 영상은 원본 커밋에 둔다.

| 운영 구간 | 처리할 실제 일 | 증거 |
|---|---|---|
| 처음 45분 | 전체 13개 파일명 확인, 담당별 조회와 엄격 검사 구현. 코딩 세션의 첫 결과가 나오면 바로 원본에서 확인 | 팀 SHA와 경로, 10편의 길이·화면 규격·트랙·프레임 타임스탬프 |
| 45~90분 | 오디오 추가, 프레임 누락, 가변 프레임률, 손상 파일, 같은 길이 영상 순서 변경을 재현. 재인코딩에 따른 차이를 구별 | 정상·오류 입력 각각의 종료 코드와 문제 파일명 |
| 90~135분 | 새 납품 도착과 재시작 후 복원, 원격 조회 장애를 로컬 테스트 저장소로 재현. 실제 변경이 들어오면 해당 팀만 재검수 | 변경 전후 SHA, 재시작 상태, 실패와 미도착을 나눈 기록 |
| 135~180분 | 총괄이 다른 경로에서 검사 명령을 재현하고 고칠 점을 코딩 세션에 돌려보낸다. 종료 시점의 세 팀 SHA와 접수 당시를 대조 | 독립 검사 결과, 수정 커밋, 기술 승인 또는 보류 사유, 대표 검토용 링크 |

시간표는 작업 예산이다. 앞 단계가 끝나면 즉시 다음 검증으로 넘어간다. 작업 카드의 180분은 새 납품을 받을 수 있는 실제 운영 시간이다. 대표 승인 없이 최종 열 편 합본을 만들거나 main에 합치지 않는다.

## 다음 세션에서 이어받을 때

총괄은 마지막 접수 시각·검사한 SHA·대기 중인 수정을 대조한 뒤 같은 카드에서 재개한다. 하위 세션을 복원할 수 없으면 같은 모델과 브랜치로 코딩 세션을 다시 열고 마지막 미완료 항목만 전달한다. 클라우드가 중단된 시간은 연속 감시 실적으로 기록하지 않는다.
