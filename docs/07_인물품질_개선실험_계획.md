## 1. 지금 인물이 원통처럼 보이는 까닭

비교 화면: 정면·45도·측면·후면을 같은 조명과 카메라로 찍었다(코드 아이 휴, 코드 모세, Blender 모세, Blender 여호수아). 삼각형 수: 휴 1,492 / 코드 모세 1,480 / Blender 모세 5,986 / 여호수아 5,554 / 제사장 4,810.

| 구분 | 진단 | 근거 (코드·화면) |
|---|---|---|
| 메시 구조 | 몸통은 둘레 12칸의 타원 고리를 위아래로 이은 로프트, 팔다리는 둘레 8칸 원기둥, 머리는 타원 공이다. Blender 모델도 매개변수 곡면(둘레 x 높이 격자)이라 모든 단면이 타원이다. 부품이 따로 겹쳐 있어 이음매에 형태 흐름이 없다 | `models.js` makeKid의 `loft(topRows, 12, ...)`, `CylinderGeometry(..., 8)`, `ball(12, 7)`. `moses.py` 머리말 1~3번 |
| 실루엣 | 어깨에서 옷자락까지 폭이 거의 같고, 옆에서 보면 두께도 같다. 팔이 몸에 붙어 덩어리가 하나뿐이다. 옷자락 끝이 곧은 고리라 땅에 닿는 선이 자로 그은 듯하다 | 측면·후면 화면에서 직사각형에 가깝다 |
| 얼굴 | 코드 모델은 타원 공에 원판 눈과 점 코. Blender 모세는 한 장 곡면에 코와 눈썹뼈를 솟게 했지만 눈두덩·광대·입 둘레의 면이 없고, 수염은 매끈한 쐐기 덩어리다 | 정면·45도 화면 |
| 의상 | 주름이 형태가 아니라 꼭짓점 색 세로 줄무늬로 칠해져 있다. 규칙적인 세로 줄이 오히려 원통을 강조한다. 천의 두께, 겹침, 허리띠에서 모이는 주름, 소매가 처지는 모양이 없다 | `moses.py`의 색 줄무늬, 화면의 등 쪽 |
| 재질 | 꼭짓점 색 한 가지와 거칠기 하나뿐이고 노멀(요철) 정보가 없다. 빛이 형태를 드러내지 못해 실루엣만 남는다 | 스타일가이드 8절(텍스처 없이 꼭짓점 색) |
| 애니메이션 | 뼈 23개, 자세를 함수로 계산한 Idle·Walk·HideFace. 옷이 다리 뼈에 그대로 붙어 걸을 때 원통째 흔들리고, 천이 늦게 따라오는 움직임이 없다 | `moses.py` 6번, 게임 화면 |

정리: 원인은 "코드로 도형을 이어 붙이는 방식" 자체에 있다. 둘레 칸 수를 늘리거나 색을 바꾸는 것으로는 원통 느낌이 사라지지 않는다. 형태를 면(plane)으로 조각하고, 천은 물리로 드리우고, 실루엣에 덩어리 대비를 주어야 한다.

참고: 2026-11-14에 만든 영상용 모세(`tools/blender/moses_real.py`)도 같은 방식(회전 곡면)이라 이 기준으로는 최종 품질이 아니다. 영상은 층으로 나눠 만들었으므로, 실험에서 승인된 모세로 모세 층만 다시 그리면 된다.

## 3. 권하는 방법

**B(Blender 고도화)와 C(Meshy 무료 웹)를 같은 모세 한 명으로 나란히 시험하고, 같은 화면 기준으로 고른다.**

- C는 품질 상한이 가장 높을 가능성이 있지만, 결과의 사용권과 가벼움(휴대폰 성능), 긴 옷의 뼈대가 문제다. 무료 웹은 0원으로 시험할 수 있다.
- B는 사용권 걱정이 없고 스타일가이드 예산에 맞추기 쉽지만, 얼굴 품질은 해 봐야 안다.
- 둘 다 마지막 손질(삼각형 줄이기, 색 굽기, 발 가리기, 뼈대와 Idle·Walk·HideFace 동작, GLB 내보내기)은 이 환경의 Blender 스크립트로 한다.
- 유료 결제는 C의 무료 결과가 B보다 확실히 좋을 때만, 상업 사용권과 비공개 저장을 위해 따로 금액을 여쭙는다.

## 4. 모세 한 명 실험 설계

### 4.1 외형 기준 (본문 근거와 감수 대상)

| 항목 | 근거 | 처리 |
|---|---|---|
| 나이: 팔십 세 무렵 | 출 7:7(바로 앞에 설 때 팔십 세), 행 7:23, 7:30 | 노인으로 그린다 |
| 직업: 장인의 양 떼를 치는 목자 | 출 3:1 | 지팡이를 든다 |
| 지팡이 | 출 4:2 (손에 지팡이가 있었다) | 모양(곧은지, 끝이 굽었는지)은 본문에 없다 → 감수 대상 |
| 신 | 출 3:5 (신을 벗으라 하심 → 신을 신고 있었다) | 발은 옷자락으로 가린다. 신을 벗는 모습은 그리지 않는다(장면목록 EX-01) |
| 수염, 머리쓰개, 옷의 겹과 색, 허리띠 | 본문에 없음 | 모두 감수 대상. "역사적으로 이랬다"고 쓰지 않는다 |
| 얼굴 | 본문에 없음 | 특정 민족 외모를 단정하지 않는다. 스타일가이드 3절(올리브~갈색 피부, 단순한 얼굴, 자세로 감정)을 따른다 |
| 하나님 표현 | 규칙서 3.3 | 이 실험은 모세 한 명만 다룬다. 불·빛 효과는 바꾸지 않는다 |

### 4.2 화풍 목표

평소 화면은 인형풍이다(지시서 6.1). 실사가 아니라 그림책풍 스타일라이즈드: 머리 대 키 약 1:6.5(지금과 비슷), 면이 살아 있는 얼굴(눈두덩, 광대, 코 등), 겹친 천과 실제 주름, 옷자락 아래가 넓어지는 실루엣. 세 아이 옆에 섰을 때 따로 놀지 않는지도 함께 본다.

| 1 | 디자인 시트: 정면·측면·후면 그림(SVG)을 그려 확인받는다. C의 이미지 입력으로도 쓴다 | Claude | 0원 |

### 4.4 기존 게임을 지키는 방법

- 실험 모델은 `web3d/assets/moses_v2.glb` 같은 새 이름으로 두고, 주소 끝에 `#moses2`를 붙였을 때만 바꿔 끼운다. 기본 화면은 지금 그대로다.
- 동작 이름(Idle, Walk, HideFace)과 크기(키 1.75m, 옷자락 끝 y=0, 정면 +Z)를 지금 모델과 같게 맞춰 game.js를 고치지 않고 바꿔 끼울 수 있게 한다.
- 대본, 퀴즈, 세 아이, 장면 진행은 건드리지 않는다. 자동 점검 3개 나이 단계를 다시 통과시킨다.

### 4.5 합격 기준 (화면으로 확인)

| 항목 | 기준 | 확인 방법 |
|---|---|---|
| 원통 느낌 | 측면·후면에서 폭과 두께가 높이에 따라 달라진다(어깨, 허리, 옷자락). 주름이 색이 아니라 형태로 보인다 | 4방향 비교 화면을 나란히 |
| 얼굴 | 45도에서 눈두덩·코·광대의 면이 보인다. 어색하거나 무섭지 않다(8세 기준) | 4방향, 게임 화면 |
| 규칙 | 발이 보이지 않는다. 무릎 꿇기·신 벗기 없음. HideFace는 선 채로 | 동작별 화면 |
| 성능 | 휴대폰에서 장면 수가 지금보다 크게 떨어지지 않는다(대표 휴대폰, 장소 이름 세 번 누르기) | 대표 확인 |
| 크기 | 삼각형, 재질 수, GLB 크기를 기록한다. 8절 예산(8,000 / 4 / 500KB)을 넘으면 대표 결정 | 자동 측정 |
| 최종 판단 | 대표가 "이전보다 낫다"고 승인 | 대표 |

코드가 실행되는 것만으로는 합격이 아니다. 화면 확인을 못 하면 통과라고 쓰지 않는다.
