## 1. 원통처럼 보이는 까닭 (진단 v0.2)

비교 화면: 정면·45도·측면·후면을 같은 조명과 카메라로 찍었다(코드 아이 휴, 코드 모세, Blender 모세, Blender 여호수아). 삼각형: 휴 1,492 / 코드 모세 1,480 / Blender 모세 5,986 / 여호수아 5,554 / 제사장 4,810.

**코드(스크립트)로 만든다는 것 자체가 원인은 아니다.** 핵심 원인은 지금 모델에 담긴 형태의 문제다. 다만 스크립트로 조각하듯 형태를 다듬는 데는 실무상 한계가 있다(5.3).

### 1.1 형상(메시)의 문제

| 원인 | 내용 | 근거 |
|---|---|---|
| 회전 대칭 단면 | 몸통·옷·머리를 둘레 x 높이 격자로 돌려 만들어 모든 단면이 타원이다. 옆과 뒤에서 직사각형 기둥으로 보인다 | `models.js` makeKid `loft(…, 12, …)`, `moses.py` 1번 |
| 단순한 인체 구조 | 어깨뼈·쇄골 덩어리, 허리와 골반의 앞뒤 기울기, 팔다리의 굵기 변화가 없다. 팔은 일정한 굵기의 관이고 몸에 붙어 덩어리가 하나뿐이다 | 4방향 화면 |
| 부족한 얼굴 조형 | 눈두덩·광대·입 둘레의 면이 없다. 수염은 매끈한 쐐기 덩어리다 | 정면·45도 화면 |
| 반복적인 의상 주름 | 주름이 규칙적인 세로 줄무늬(색)이거나 고른 잡음이라 기계적으로 보인다. 천의 두께, 겹침, 허리띠에서 모이는 주름, 소매의 처짐이 없다 | `moses.py` 색 줄무늬, 2026-11-14 영상용 모세(`moses_real.py`)의 잡음 주름 |
| 옷자락과 실루엣 | 어깨에서 옷자락까지 폭과 두께가 거의 같고, 옷자락 끝이 곧은 고리다 | 측면·후면 |

### 1.2 재질(색·노멀)의 문제 (형상과 따로 본다)

| 원인 | 내용 |
|---|---|
| 꼭짓점 색 한 가지 | 면마다 색 하나라 작은 요철과 직물 결이 없다(스타일가이드 8절: 텍스처 없이 꼭짓점 색) |
| 노멀·AO 부족 | 노멀맵이 없고, 굽힌 그늘(AO)도 꼭짓점 단위로만 있어 주름 골이 얕다 |
| 조명 | 게임은 반구광 + 방향광 하나뿐이라 형태를 드러내는 테두리 빛이 약하다(재질이 좋아도 덜 보인다) |

### 1.3 애니메이션의 문제

옷이 다리 뼈에 그대로 붙어 걸을 때 원통째 흔들린다. 천이 늦게 따라오는 움직임이 없다.

### 1.4 고치는 수단 (천 시뮬레이션은 필수가 아니다)

| 수단 | 쓰는 곳 | 비고 |
|---|---|---|
| 수동 조형(스크립트로 정점 다듬기, 형태 키) | 몸 덩어리, 얼굴 면, 옷 겹침 | 손 조각보다 느리고 한계가 있다 |
| 천 시뮬레이션(정지 자세로 한 번 드리우기) | 옷자락·겉옷·머리쓰개의 자연스러운 주름 | 이 환경에서 작동 확인(2026-11-14). 결과는 고정 메시로 굳히고, 게임 안에서 실시간으로 돌리지 않는다 |
| 스키닝(가중치 정리) | 걸을 때 옷의 변형 | 다리 대신 골반·옷자락 보조 뼈에 나눠 붙이면 원통째 흔들리는 것을 줄일 수 있다 |
| 텍스처 굽기(색 + AO + 요철을 한 장에) | 재질 | 8절 예외가 필요하다(6.3) |

## 2. 비교할 제작 방식 세 가지

세 방식 모두 **같은 디자인 시트(`tools/art-src/gen_moses_sheet.py`), 같은 카메라 4방향, 같은 조명**으로 비교하고, **형상 품질과 재질 품질을 따로** 매긴다(형상은 회색 재질로 한 번, 재질은 원래 재질로 한 번 찍는다).

| 방식 | 내용 | 형상 기대 | 재질 기대 | 사용권 | 비용 | 이 환경에서 |
|---|---|---|---|---|---|---|
| B. Blender 스크립트 고도화 | 지금 `moses.py`를 바탕으로 회전 대칭을 깨고, 몸 구조와 얼굴 면을 다듬고, 옷은 천 시뮬레이션이나 수동 조형으로 | 중간 ⚠️ | 중간 | 우리 것 | 0원 | 됨 |
| B-2. 고품질 인체 베이스 메시 + Blender | Blender Studio의 Human Base Meshes(CC0, 49MB .blend, v1.4.1)에서 얼굴과 몸을 가져와 모세 비율로 고치고, 옷은 B와 같은 방법 | 좋음 ⚠️ (얼굴과 몸의 면이 이미 있다) | 중간~좋음 | CC0(검색 요약, ⚠️원문 미확인) | 0원 | 내려받기 주소가 막혀 있어 5.4의 전달 방법이 필요 |
| C. Meshy AI 생성 | 디자인 시트와 글 설명으로 생성 → Blender에서 손질 | 좋음 ⚠️ | 무료판은 텍스처 없이 받을 가능성이 있다(3절) | 무료 CC BY 4.0 / 유료 상업 사용권 | 무료 또는 유료(3절) | 웹은 대표 PC에서. API는 막힘 |

검토했으나 뺀 것: Tripo(무료판 사용권이 출처마다 엇갈리고 이 환경에서 막힘), 공개 AI 모델 직접 실행(그래픽 카드 없음), 에셋 스토어 인물(고대 복식 인물 팩을 찾지 못했고, 웹용 GLB로 빼 쓰는 것은 약관 위험).

## 3. Meshy 무료 플랜 조건 (확인 상태 구분)

이 환경에서는 meshy.ai와 docs.meshy.ai 주소가 막혀 원문을 열지 못했다. 아래는 공식 페이지의 검색 요약과 제3자 자료다.

| 항목 | 내용 | 확인 상태 |
|---|---|---|
| 무료 생성 | 월 100 크레딧, 카드 불필요, 크레딧 추가 구매 불가 | 공식 가격 페이지(검색 요약) |
| GLB 다운로드 | 월 10개까지, Meshy 6 Lite 모델 | 공식 가격 페이지(검색 요약) |
| 텍스처 포함 다운로드 | 무료판은 텍스처 없는 다운로드만 된다는 제3자 자료 2건. 무료 GLB에 UV·재질이 없었다는 사용자 시험 1건 | **미확인** (공식 문장 없음) |
| 사용권 | 무료 CC BY 4.0(출처 표기 시 상업 사용 가능), 유료 상업 사용권 | 공식 문서(검색 요약) |
| 무료 결과의 공개 여부 | 알 수 없음 | **미확인** |
| API | Pro 이상이라는 자료 | 제3자, **미확인** |
| 유료 가격 | Pro 월 20달러(약 2.7만 원, 1달러 1,360원 추정), 연간 결제 시 20% 할인 | 공식 도움말(검색 요약). 다른 자료는 요금제 이름과 값이 다르다 |

판단: 무료판으로는 **형상 비교까지만** 확실히 할 수 있다. 재질(텍스처)까지 비교하려면 유료가 필요할 수 있다. **유료 결제는 금액과 용도를 적어 대표 승인을 받은 뒤에만 한다.** 대표가 가입하면서 계정 화면의 다운로드 조건을 직접 확인해 주는 것이 가장 빠르다.

## 4. 외형 기준 (성경적 표현)

| 항목 | 본문 | 처리 |
|---|---|---|
| 나이 | 본문은 호렙 산 사건 때 모세의 나이를 직접 말하지 않는다. 행 7:23(사십 세)과 7:30(사십 년이 지나 떨기나무 불꽃 가운데 나타남), 출 7:7(바로 앞에 설 때 팔십 세)에 비추어 노년으로 그린다 | "팔십 세"로 확정해 쓰지 않는다. 노년이라는 해석은 감수 대상 |
| 목자, 지팡이 | 장인의 양 떼를 쳤다(출 3:1). 손에 지팡이가 있었다(출 4:2) | 지팡이를 든다. 모양(곧은지, 끝이 굽었는지)은 본문에 없다 → 감수 대상 |
| 신 | 신을 벗으라고 하셨다(출 3:5) → 신을 신고 있었다 | 발은 옷자락으로 가린다. 신을 벗는 모습은 그리지 않는다(장면목록 EX-01) |
| 수염, 머리쓰개, 옷의 겹과 색, 허리띠, 피부색, 얼굴 생김새 | 본문에 없음 | 모두 감수 대상. "역사적으로 이랬다"고 쓰지 않는다. 특정 민족 외모를 단정하지 않고 스타일가이드 3절을 따른다 |
| 동작 | 보러 감(3:3-4), 대답(3:4), 얼굴을 가림(3:6) | HideFace는 선 채로. 무릎 꿇기, 신 벗기 없음. 그 밖의 동작(Idle, Walk)은 본문 사건이 아닌 일반 동작 |
| 하나님 표현 | 규칙서 3.3 | 이 실험은 모세 한 명만 다룬다 |

## 5. 권하는 제작 방식, 한계, 비용, 절차

### 5.1 권하는 방식: B-2를 주력으로, C를 비교군으로, B는 시간 제한 대조군으로

- **B-2 주력**: 얼굴과 몸의 형태(눈두덩, 광대, 어깨 덩어리)는 스크립트로 처음부터 만들기 가장 어려운 부분이다. 이미 잘 만들어진 CC0 베이스 메시에서 시작하면 그 부분을 사람 손으로 조각한 품질로 얻는다. 사용권이 깨끗하고 삼각형 예산도 우리가 정할 수 있다.
- **C 비교군**: 몇 분 만에 조각한 듯한 결과가 나와 품질 상한을 보여 준다. 다만 무료판은 텍스처와 사용권 제약이 있고, 긴 옷 인물의 뼈대와 손질이 어렵다.
- **B 대조군 (2시간 제한)**: 지금 방식으로 어디까지 오르는지 확인하는 기준선이다. 시간 안에 원통 느낌이 풀리지 않으면 그것도 결과로 기록한다.

### 5.2 단계 (단계마다 화면으로 확인하고 다음으로 간다)

| 단계 | 내용 | 산출물 | 누가 | 비용 |
|---|---|---|---|---|
| 0 | 기준 화면(끝냄), 디자인 시트(끝냄, 대표 확인 필요) | 4방향 화면, 시트 | Claude | 0원 |
| 1 정지 모델 | B·B-2·C를 같은 자세(A자세)의 정지 모델로 만든다 | 세 모델의 형상 4방향(회색) + 재질 4방향 + 게임 속 정지 화면 | Claude, 대표(C 생성) | 0원 |
| 1 판정 | 형상과 재질을 따로 매겨 하나를 고른다 | 비교표 | **대표 결정** (GPT 검토 가능) | |
| 2 움직임 | 고른 한 모델만 뼈대·가중치·Idle·Walk·HideFace | 동작별 화면, 짧은 영상 | Claude | 0원 |
| 3 최적화 | 8절 예산판과 예외판 두 가지로 내보내 크기·성능을 잰다 | 측정표 | Claude | 0원 |
| 4 게임 시험 | 주소 끝 `#moses2`로만 바꿔 끼워 실제 장면(올려다보기, 지켜보기, 걷기)에서 비교. 세 아이와 나란히 | 게임 화면, 자동 점검 3단계 | Claude + 대표(휴대폰) | 0원 |
| 5 승인 | 대표가 "이전보다 낫다"고 승인하면 기본 모델로 바꾼다(기존 모델 파일은 남긴다) | | 대표 | |

세 방식 모두에 뼈대와 동작까지 하는 것은 비용 대비 효과가 낮아, **1단계는 정지 모델로만 비교하고 움직임은 고른 하나에만** 한다(GPT 2번 의견을 단계로 나눠 반영).

### 5.3 예상 한계

| 한계 | 영향 | 대비 |
|---|---|---|
| Claude는 붓으로 조각하지 못하고 스크립트로만 형태를 다룬다 | B의 얼굴 품질 상한이 낮다 | B-2로 얼굴·몸을 베이스 메시에서 가져온다 |
| 이 환경에 그래픽 카드가 없다 | 렌더와 시뮬레이션이 느리다(장면 한 장 수십 초~수 분) | 정지 화면 위주로 비교 |
| 외부 사이트가 막혀 있다 | 베이스 메시와 Meshy 결과를 직접 받을 수 없다 | 5.4 |
| 긴 옷 인물의 자동 뼈대 | C의 자동 뼈대는 옷자락을 다리로 착각할 수 있다 | 뼈대는 Blender에서 직접 넣는다 |
| 세 아이는 단순한 코드 모델로 유지된다(8절) | 모세만 좋아지면 화풍이 따로 놀 수 있다 | 4단계에서 나란히 보고, 필요하면 아이들 개선을 별도 안건으로 올린다(이번 범위 밖) |
| 전체 장면의 성능 | 휴대폰 장면 수는 양 떼, 불, 빛 번짐까지 합친 값이다 | 같은 휴대폰에서 기존 모세와 새 모세를 바꿔 차이를 잰다 |
